# 在 dsh 中运行 Jev 星露谷 Agent

打开 dsh 同源的 `/stardew` 运行面板，输入一次目标，Jev 会持续观察、选择动作并执行。聊天模型不是自主游玩的依赖。

## 启动并操作

需要 Node.js 22+、pnpm、dsh，以及可访问 Jev 的 OpenRouter Key。当前接口基线为 dsh `0.1.5-rc.1`。

1. 在仓库根目录执行 `pnpm install --frozen-lockfile`。
2. 复制 `.env.example` 为 `.env`，填写 `OPENROUTER_API_KEY`；也可在 dsh 凭据中配置同名 Key。
3. 体验模拟农场执行 `pnpm start --mock --jev`；连接真实游戏执行 `pnpm start --jev`。
4. 打开 dsh 聊天，点击右上角“农场小助手”，或任务卡片中的“查看农场”。面板在右侧展开，可收起或调整宽度；收起不停止任务。独立页面为 `http://127.0.0.1:3080/stardew`。
5. 点击“观察”核对模式与存档，再输入目标，点击“开始农活”。单步位于“任务设置与完成条件”中。

浏览器未登录时，首页显示“连接你的工作区”。将启动终端中 `dsh web:` 后的完整链接粘贴进去，点击“连接工作区”。也可在项目根目录运行 `pnpm open`，直接在默认浏览器打开登录入口；`pnpm open --print` 输出当前有效链接，方便复制到无痕或其他浏览器。服务重启后请使用新链接。登录不新建聊天，也不启动游戏任务。

已打开的工作区会检测本机 dsh 是否断开或重启。断线期间页面阻止继续发送；服务恢复后自动刷新到新实例，登录状态失效时回到连接页，避免消息只显示在旧标签页而没有提交到新服务。

无头自动化需要在同一个 browser context 中打开完整登录链接，等待地址回到 `/`、聊天输入框出现后再操作；新 context 需要重新登录。登录链接只发送给同一个本机服务，已有 Cookie、API 鉴权和有效期由 dsh 管理。

完成项目 `setup` 后，`pnpm test:login` 使用当前 dsh 的真实鉴权与 HTTP 服务验证登录入口，不启动游戏或调用模型。

例如输入“探索农场，找到农舍和适合种植的空地”。Jev 自己选择移动和交互，面板显示游戏观察、任务和农场日记。初次观察前展示欢迎插画；观察后切换为结构化地图，并显示当前季节日历、时间和体力条。背包显示槽位顺序与手持物品；界面槽位从 1 显示，CLI 与工具参数 slot 仍从 0 开始。实际模型、类别与动作概率收在“Jev 决策与运行详情”中。

“暂停 Agent”会等待在途请求和动作停稳；“继续任务”重新观察后接续任务。暂停时可以修改目标，继续后清除旧的完成条件。“停止”结束本次运行。修改完成条件或用完预算后，先停止当前任务，再点击“开始农活”创建新任务。

游戏时钟遵循游戏自身规则；暂停 Agent 只停止自动控制。聊天界面的停止按钮只取消聊天调用，游玩通过运行面板或专用工具停止。

## 完成条件与能力范围

自由目标可以直接运行。Jev 判断完成后显示“待你复核”，并保留观察证据。展开“任务设置与完成条件”可以指定地图、新增观察格数、新种植作物及数量、当日浇水、日期推进、本次浇水作物格数和水壶补水；全部条件通过才显示“已核验完成”。

例如“种下 5 颗防风草并浇水，然后回屋睡觉”：在条件中填写作物 ID `24`、数量 `5`，勾选当日浇水和日期推进。条件只决定验收，不编排动作。种子、工具、土地和体力必须通过当前游戏状态与已支持操作获得。

默认只给需要水的作物提供浇水候选，跳过空地、已浇水及无需水的作物。确需提前浇空耕地时勾选“允许预先浇空耕地”。水壶不足时可寻找水源、靠近并补水；补水使用正常游戏工具动作，以水量增加验收，补水后继续原目标。

当前支持移动、选择物品、耕地、播种、浇水、水壶补水、斧头／镐、场景交互和对话选项。商店购买、容器取放和其他菜单仍需补齐对应基础接口；遇到缺口会展示具体状态，不将未执行操作记为完成。

## 真实游戏与更新

编译基线为 macOS、Stardew Valley 1.6.15、SMAPI 4.5.2、.NET 6 SDK。`pnpm start --jev` 在游戏未运行时构建、备份并安装 Mod，然后启动 SMAPI 与 dsh。

加载单人测试存档后即可切回面板；当前 Mod 支持失焦后台运行，游戏时间也会继续推进。首次领取种子如果停在举物动画，按游戏动作键继续。已有用户存档先备份；游戏测试使用专用存档。

游戏已运行时 start 连接当前 Mod。修改 Mod 源码后，需要正常保存并退出游戏，再执行 start 才会安装新构建。新版农务候选使用 `diggable`、`tool`、`category`、`needsWater`、`refillable`、`waterCapacity` 观察字段，旧 Mod 缺字段时面板会提示。自定义游戏路径使用 `--game-path`；依赖路径支持 `.env` 中的 `DOTNET_PATH` 和 `DSH_PATH`。

## 配置与记录

| 配置或数据 | 行为 |
| --- | --- |
| Jev 模型 | OpenRouter `~typesafe/jev-latest`，专用 Decisions API |
| 请求时限 | 插件 `jevTimeoutMs=8000` |
| 最低置信度 | 插件 `jevMinConfidence=0.35`；连续不足时停止，不调用另一模型接管 |
| 默认预算 | 100 次模型请求、15 分钟运行时间；暂停时间不计入 |
| 运行记录 | `work/runs/jev-<run-id>/events.jsonl`、`status.json` |
| dsh 数据 | 仓库独立的 `work/dsh/`，重复 setup 保留 |
| 模式配置 | `work/stardew.patch.yml`；真实端口 17654，模拟端口 17655 |

状态中分别记录实际 `model`、`decisionId`、答案概率、置信度、耗时和用量。控制循环只调用 Jev；这不包括用户另行发起的 dsh 聊天。重启后保留日志，但不自动恢复游戏操作，需重新核对现场后启动。

## 让大模型规划，Jev 执行

在 dsh 中配置聊天模型后，可以直接输入：

> 读取 stardew skill。种下 5 颗防风草并浇水，然后回屋睡觉。请按阶段规划，让 Jev 自主执行；缺水自行找水源补水，受阻时根据证据判断。

模型用 `stardew_plan_start` 传入总目标和当前阶段。Jev 的每轮请求同时保留总目标约束和阶段目标，并自主探索、选择动作。阶段完成、受阻或待复核后，插件把游戏观察、资源变化、错误和日志位置作为插件消息送回原聊天；大模型再调用 `stardew_plan_next` 调整或接续，最后用 `stardew_plan_finish` 汇总。

聊天任务卡片显示本次调用的状态和目标，“查看农场”打开当前共享任务面板。无需再次开始任务。切换聊天不会为同一个游戏创建第二个控制器；旧卡片的调用记录保持原样。

默认最多 4 个阶段，共享 100 次 Jev 调用和 15 分钟总时限；该时限包含大模型等待时间。模型不能用接续重置预算。阶段记录保留各自的完成判据；大模型汇总完成与游戏核验完成分别标记。界面“规划与阶段”可查看总目标、阶段、回传次数、预算与阶段证据。

面板中的手动开始、暂停、继续或停止会结束自动阶段接续，旧回传无法再次接续计划。游戏或存档切换后也需重新发起。简单目标仍可用 `stardew_run_start` 独立运行，不自动回传规划模型。

控制工具为 `stardew_run_start`、`stardew_run_status`、`stardew_run_pause`、`stardew_run_resume`、`stardew_run_stop`。Jev 启用时保留 doctor、snapshot、screenshot、status、stop 诊断工具；原子写操作由控制器统一执行。参数见[随包 skill](../packages/dsh-plugin/skills/stardew/SKILL.md)。

skill 随插件自动注册。修改 skill 或插件源码后执行 `pnpm build:ts` 并重启 dsh；只刷新网页不会让服务重新读取 skill。聊天汇报围绕目标和农场证据，区分模拟农场、真实游戏、模型建议结束与游戏核验完成。

## 故障处理

| 状态 | 操作 |
| --- | --- |
| `NOT_CONNECTED` / `NO_SAVE_LOADED` | 检查 SMAPI、Mod 与单人存档 |
| `MISSING_CREDENTIAL` / `HTTP_401` | 设置 OpenRouter Key；修改 .env 后重启 dsh |
| `HTTP_402` / `HTTP_429` | 检查额度或等待限流恢复后继续 |
| `UNSUPPORTED_MENU` | 当前菜单尚无可执行选项，记录菜单类型并补齐接口 |
| `NO_PROGRESS` / `PATH_BLOCKED` | 查看重复行动与障碍；若仅在后台发生，确认已安装当前 Mod 并重启游戏 |
| `WORLD_CHANGED` | 存档或游戏实例已改变，核对后创建新任务 |
| `BUDGET_EXHAUSTED` | 本次停止，保留记录；核对目标后用新的预算启动 |

`pnpm check` 检查控制逻辑、协议和模拟环境；`pnpm test:dsh` 检查真实注册器及 CLI 子进程。模型替身、真实 Jev 请求和真实游戏验证分别记录，不能互相替代。设计见 [Jev 自主游玩设计](jev-runtime.md)。
